Color Tools API Reference

Version: 7.1.2

Welcome to the Color Tools API documentation! This library provides comprehensive color science tools for accurate color space conversions, perceptual color distance metrics, and color matching.

🎨 Three Ways to Use Color Tools:

  1. As a library: from color_tools import rgb_to_lab

  2. As a CLI tool: python -m color_tools color --name coral

  3. As installed command: color-tools filament --list-makers (needs pip install)

Quick Start

from color_tools import rgb_to_lab, delta_e_2000, Palette

# Convert RGB to LAB
lab = rgb_to_lab((255, 128, 64))

# Find nearest CSS color
palette = Palette.load_default()
nearest, distance = palette.nearest_color(lab)
print(f"Nearest color: {nearest.name}")

CLI Commands

The CLI provides eight commands:

  • color - Search CSS colors by name or find nearest color

  • harmony - Generate styled LCH color harmonies

  • filament - Search 3D printing filaments with filtering (maker, type, finish)

  • convert - Convert between color spaces and check gamut

  • name - Generate descriptive names for RGB colors

  • validate - Validate if hex codes match color names (fuzzy matching + Delta E)

    • Optional: Install [fuzzy] extra for improved fuzzy matching: pip install color-match-tools[fuzzy]

  • cvd - Color vision deficiency simulation and correction

  • image - Image color analysis and manipulation

    • Requires: Install [image] extra: pip install color-match-tools[image]

See the Usage Guide for detailed CLI examples.

Selected Data Models

The library uses typed dataclasses and models to represent colors, filaments, export configuration, and results. Record and result types are immutable where their contracts require it; export metadata and option objects remain mutable.

  • ColorRecord - CSS colors with precomputed values in all color spaces

  • ColorLoadEvent / ColorLoadReport - Structured user-color merge changes and counts

  • FilamentRecord - 3D printing filaments retaining source RGB components and an effective color

  • FilamentFilterCriteria - Reusable maker, type, finish, color, and TD filters

  • HarmonyColor / HarmonyResult - Ideal and displayable LCH harmony results

  • ColorValidationRecord - Color name/hex validation results with fuzzy matching

  • PaletteMetadata / PaletteExportData - Palette-level export metadata and ordered colors

  • HexExportOptions / HueForgeExportOptions - Typed per-export behavior

  • UserColorExportPlan / UserColorExportResult - Stateful user-color merge planning and apply results

  • UserFilamentExportPlan / UserFilamentExportResult - ID-based user-filament merge planning and apply results

  • ColorCluster - Image color clusters from k-means analysis (requires [image] extra)

  • ColorChange - Luminance redistribution results for HueForge (requires [image] extra)

Color Input Contracts

The public helpers below share one canonical implementation. RGB validation requires exactly three built-in integer channels in 0-255. Hex parsing accepts RGB/RGBA short and long forms; alpha is validated and discarded.

color_tools.conversions.validate_rgb(rgb)[source]

Check that RGB contains exactly three built-in integers in 0-255.

Channels are interpreted as red, green, and blue, in that order. Both endpoints are allowed. Booleans, floats (including integral floats), and subclasses of int are rejected because each channel must have type int. Values are not converted, rounded, or clamped, and the input is not modified. Only tuple and list containers are accepted.

Parameters:

rgb (object) – Three 8-bit RGB channels to validate.

Return type:

None

Returns:

None when all checks pass.

Raises:

ValueError – If the channel count is not three, a channel is not a built-in integer, or a channel is outside the inclusive 0-255 range.

Example

>>> validate_rgb((255, 127, 0))
color_tools.conversions.parse_hex_colors(hex_code)[source]

Parse ordered components separated by -, spaces, comma, _, /, :, or ;.

ASCII spaces may surround punctuation and the complete compound value. Repeated punctuation and empty components are errors, not discarded colors. All components are validated, including alpha, and duplicates are retained. Any positive number of components is supported. Each uses the single-color RGB/RGBA/RRGGBB/RRGGBBAA grammar; alpha is validated then dropped.

Parameters:

hex_code (object) – Original single or compound hex string.

Return type:

tuple[tuple[int, int, int], ...]

Returns:

An immutable ordered tuple of RGB triples.

Raises:

ValueError – If the input type or any component is invalid.

Example

>>> parse_hex_colors("#f00 / #00f")
((255, 0, 0), (0, 0, 255))
color_tools.conversions.normalize_hex(hex_code)[source]

Return a validated single color in canonical uppercase #RRGGBB form.

Short forms are expanded and valid CSS/PNG alpha-last components are discarded according to parse_hex()’s contract.

Parameters:

hex_code (str) – RGB, RGBA, RRGGBB, or RRGGBBAA with an optional leading #.

Return type:

str

Returns:

The parsed RGB color formatted as uppercase #RRGGBB.

Raises:

ValueError – If the input type or syntax is invalid.

Example

>>> normalize_hex("#a1c8")
'#AA11CC'
